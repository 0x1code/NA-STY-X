# NA&STY-X v0.3 — исследовательское ядро

**Статус:** работающая экспериментальная конструкция, без установленных границ стойкости. Реализации: `nastyx-engine` и `engine_v3.py`. v0.2 остаётся отдельным историческим ядром; автоматического переключения версий нет.

## Параметры

Блок 128 битов, мастер-ключ 256 битов, половины по 64 бита. По умолчанию 24 раунда; явные исследовательские варианты 8, 12, 16, 20, 24. Все суммы ограничиваются по модулю 2^64. Внешние слова — big-endian. Внутренняя байтовая подстановка — little-endian.

## Собственная S-box

Исходная таблица — кандидат 18 генератора v0.2. Выполнены два публичных детерминированных локальных поиска:

1. `optimize_sbox.py`: seed 20261011, 30 000 перестановок двух элементов; минимизация суммы `DDT[a,b]^4` для ненулевых `a`, принимаются изменения с delta <= 0.
2. `optimize_linear.py`: seed 20261012, 4 000 перестановок; минимизация суммы `W[a,b]^8` для ненулевых масок, то же правило приёма.

Приращения пересчитываются инкрементально, затем полные таблицы проверяются повторным независимым вычислением. Итоги сохранены в `sbox-optimized-v1.json` и `sbox-linear-optimized-v1.json`. Замороженная таблица — `tests/vectors/sbox-v0.3.hex`; Rust использует её числовую константу, Python — собственную реализацию шифра с теми же опубликованными значениями. Для воспроизведения поиска использована Python 3.12.10.

| Метрика | Собственная v0.2 | Собственная v0.3 |
|---|---:|---:|
| Дифференциальная равномерность | 10 | 8 |
| Максимальный модуль Уолша | 64 | 52 |
| Минимальная нелинейность компонент | 96 | 102 |

Новая таблица лучше предыдущей по этим метрикам, но не оптимальна и не доказывает стойкости. Алгебраические степени ненулевых компонент — от 6 до 7; фиксированных точек нет, противоположные фиксированные точки есть. Их отсутствие или наличие отдельно не определяет безопасность.

## Раундовая функция

```text
q = little_endian_bytes(x XOR k)
b[j] = S[q[P[j]]], P = [2,5,0,7,4,1,6,3]
z = little_endian_word(b)
y = (z + ROTL64(z,17)) XOR ROTL64(z,41)
y = (y + ROTL64(y,31)) XOR ROTL64(y,23)
F(x,k) = (y + ROTL64(y,11)) XOR ROTL64(y,37) XOR k
```

Три последовательных ARX-преобразования добавлены для распространения изменений между частями слова. Это решение исследовательское; хороший лавинный эффект не даёт доказательства защиты от дифференциальных или линейных атак.

## Расписание ключей

Разбить мастер-ключ на big-endian слова `s0,s1,s2,s3`; `G = 0x9E3779B97F4A7C15`.

```text
c = G*(i+1) mod 2^64
t = F(s0 XOR ROTL64(s1,13), s2 XOR c) XOR s3
ki = F(t,c)
(s0,s1,s2,s3) = (
    old_s1 XOR ROTL64(old_s0,7),
    old_s2 + ROTL64(ki,11),
    old_s3 XOR ROTL64(old_s1,29),
    ki + old_s0
) mod 2^64 where applicable
```

Последняя нелинейная обработка включает влияние четвёртого слова: оно больше не просто XOR-ится в готовый первый раундовый ключ. Расписание не является проверенным KDF. Не установлено отсутствие всех слабых, эквивалентных или связанных ключей.

## Преобразование блока

Для каждого ключа `(L,R) = (R,L XOR F(R,ki))`; выход `L || R` без дополнительного обмена. Обратное преобразование в обратном порядке ключей: `(L,R) = (R XOR F(L,ki),L)`. Это доказывает обратимость, не секретность. Расписания вариантов являются префиксами; варианты не разделены доменами.

## Исследования и воспроизведение

`full_width_v3.py` проверяет настоящую 64-битную F и 128-битный шифр: SAC на 512 образцах для трёх раундовых ключей, выборочные корреляции однобитных масок, семейство 1024 мастер-ключей и изменение каждого бита трёх базовых ключей. Диффузия всего шифра измерена на 32 парах для всех пяти вариантов. Публичные RNG используются только для экспериментов.

В проверенном семействе 1024 расписания различны; внутри них повторяющихся слов не найдено. Это ограниченный отрицательный результат. Средняя дистанция F составила около 32 из 64, шифра на 24 раундах — 63,9709 из 128. Максимальные выборочные корреляции не интерпретируются как атака: выборка мала, проверяется много масок.

`reduced_model_v3.py` дополнительно перебирает все 65 536 входов отдельной 16-битной модели для двух ключей и выбранных разностей/масок. Модель заменяет ширину слова на 8, сохраняет таблицу S и рекурсии с усечением; байтовая перестановка исчезает, вращения сокращаются по модулю 8. Поэтому её вероятности нельзя переносить на исходный шифр. В частности, на 17 и 41 получается одна и та же величина вращения. Результаты — в `reduced-model-v3.json`.

Отрицательное наблюдение: максимум выбранных дифференциалов toy-модели на 4 раундах достиг 0,003174 против 0,000366 у прежней модели. На 3 раундах сохраняется 0,046875. Улучшение таблицы не улучшило все показатели уменьшенной конструкции. Это не атака на полную v0.3, но результат сохранён как направление для дальнейшего исследования, а не скрыт настройкой модели.

```powershell
py -3 research/optimize_sbox.py --output research/results/sbox-optimized-v1.json
py -3 research/optimize_linear.py
py -3 research/full_width_v3.py
py -3 research/reduced_model_v3.py --output research/results/reduced-model-v3.json
py -3 research/generate_v3_vectors.py --check
cargo test --workspace --locked
```

## Не закрыто

Табличные обращения зависят от секретов; постоянное время и гарантированное стирание памяти не обеспечены.
